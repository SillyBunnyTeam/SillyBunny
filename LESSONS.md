The sections go from the most fixes to the fewest. "No test" lists fixes that shipped without a test that guards them.

### Mobile, viewport and WebKit

This is the largest class by a wide margin.

- **Breaks:** viewport or virtual keyboard changes hide the composer or detach the shell.
- **Files:** `public/css/sillybunny-mobile-shell.css`, `public/css/sillybunny-tabs.css`, `public/style.css`, `public/scripts/sillybunny-tabs.js`.
- **Tests:** `tests/mobile-keyboard-focused-input-scroll.test.js`, `tests/mobile-shell-lifecycle-wiring.test.js`, `tests/expanded-editor-touch.e2e.js`, `tests/openrouter-picker-touch.e2e.js`, `tests/webkit-prefix-companions.test.js` (WebKit prefix parity, #562).
- **Limit:** `tests/mobile-ios26-keyboard-layout.e2e.js` simulates `visualViewport` in Chromium. It does not test real Safari.
- **Limit:** `tests/webkit-prefix-companions.test.js` checks `backdrop-filter` and `user-select` in fork `.css`, inline CSS in JavaScript and HTML, and bundled agent templates. It skips the upstream-origin files in `tests/fixtures/upstream-origin-public-files.json` and does not check camelCase style properties such as `style.backdropFilter`. It uses its own brace scanner because `@adobe/css-tools` 4.4.4 does not parse CSS nesting and drops rules in `public/style.css`.
- **Side-panel sheets:** adopted upstream panel sources can retain mobile `100dvw` sizing; constrain the source and its descendants to the panel. Size sheets from available space, not their intrinsic height: a flex child with percentage sizing can otherwise collapse the source and its nested scroller to zero. Keep same-side docked panels split across the measured chat-shell height. Tests: `tests/side-panel-adapters.e2e.js` (390×844, 360×740, 1440×900, split panels) and `tests/mobile-shell-smoke.e2e.js` (MovingUI containment).
- **Lazy images in a closed `<details>`:** Chromium still fetches an `<img loading="lazy">` inside a closed `<details>`, so a large image in a collapsed expander must get its `src` only when the expander first opens. Found with the former Home "More Assistants" expander (`342c557dd`), which the one-column Home removed; no current code depends on it.
- **Closed menus stay in the DOM:** every registered side panel keeps its `role="menu"` element (`public/scripts/sillybunny-editor/side-panel.js:268–269`) while closed, so "is a menu open?" must test for a visible box, not for a `[role=menu]` match. A plain match made the former Bundled Extras page inside Home (`342c557dd`) ignore Escape forever; that page is now a window, whose dialog frame handles Escape, so no current code depends on this.
- **Side-panel sheets without a composer:** a phone side-panel sheet sits above `#form_sheld`, and Home hides the composer (`#sheld[data-sb-home='on'] > #form_sheld { display: none }`, `public/css/sillybunny-home.css`). A `display: none` composer has an all-zero rect, so a sheet anchored to its top got zero height. `getSheetAnchorTop()` in `public/scripts/sillybunny-editor/side-panel.js` uses the bottom of `#sheld` when the composer has no layout box. Tests: `tests/unit/side-panel.test.js`, `tests/home-state.e2e.js` (a sheet opened on Home is taller than 100px and stays inside `#sheld`).
- **Docked side-panel bounds:** side panels also carry `.sb-dialog--window`, so the Window's `max-height: 90dvh` can clip a panel below the chat shell. Remove that cap from docked panels; `tests/side-panel-adapters.e2e.js` checks the panel against `#sheld` at 1440×900. Introduced by `70801186d`.
- **Detached modal content:** moving mobile chat tools into a shared dialog without hiding the source fragment leaves its search field painted in the document. This was introduced by `aa19e952a` and affected the Characters mobile opening path as well as Toggle Panels. Keep detached dialog content hidden and inert until the frame owns it, then hide it again after disposal. Test: `tests/mobile-character-toggle-and-panels.e2e.js`.
- **Mounted list spacing:** legacy tag controls carry a top margin, and the mobile drawer can apply a more specific margin on top. Reset that margin only inside the mounted Characters/Groups filter row; keep its 40px desktop and 44px mobile target. Test: `tests/character-list.e2e.js` (`Groups filter toolbar avoids extra vertical padding`).
- **Mobile editor labels:** a select that should sit below its label needs the shared combo row's `wide: true` mode. Otherwise its intrinsic-width suffix can squeeze labels such as Group Folder into multiple lines. Test: `tests/group-editor-member-lists.e2e.js` (`group folder label stays on one line on mobile`).
- **Popup scroll:** upstream `popup.css` sets `min-height: fit-content` and hides overflow on tall desktop popups, which clips the final rows. The tier frame fixes this; `tests/popup-scroll.e2e.js` checks the last row and visible response. Characterized by `e78207e03`, framed by `5d0d2dd9b`.
- **No test:** #438 (iOS overscroll blanks the page, keyboard moves the composer).
- **Fixes:** #658 (composer stays above the iOS keyboard), #840 (touch scroll in expanded mobile editors), #914 (pickers open during scroll).
- **Labels that may not fit:** a width breakpoint cannot decide whether a text label fits, because the label's width depends on the user's font size (`--fontScale`, the Global Font Size slider) and on the translation. The Home assistant card footers first used fixed container-query widths; at a 20px font or with the French "Start new chat", the ⋮ button sat up to 135px outside the card. `public/scripts/sillybunny-home/footer-fit.js` measures each footer with both labels shown (one read pass, one write pass, in an animation frame so the write cannot loop the `ResizeObserver`) and sets `data-sb-footer-compact` so both labels hide together; a CSS safety net (`min-width: 0`, ellipsis) keeps a miss inside the card. `scrollWidth` alone missed buttons that spilled into the footer's end padding, so the check compares the buttons' span with the content box. Tests: `tests/unit/sillybunny-home-footer-fit.test.js`, `tests/home-layout.e2e.js` (20px font, long labels, every card width).
- **Measure the placement you are testing for:** `header-fit.js` (`public/scripts/sillybunny-home/`) keeps the Home title centred on the column and moves the version below it when the version beside the title would touch the main menu button. Each pass removes `data-sb-version-below` first and measures the beside placement, so the answer depends only on current widths and cannot oscillate; below the title the version has zero inline size, so a text change resizes nothing, and a `MutationObserver` on the version triggers a pass. A test helper that measured the version in its current placement never found the switch point at 390 and 360. Tests: `tests/unit/sillybunny-home-header-fit.test.js`, `tests/home-layout.e2e.js` (title centred at every width and at 20px text, version below on narrow phones).
- **Popovers and the visual viewport:** a fixed popover is placed in layout-viewport coordinates, but the user sees only the visual viewport, which is smaller while zoomed in or while an on-screen keyboard is open. `getVisibleViewport()` (`public/scripts/sillybunny-action-menu.js`) clips `bounds` to the visual viewport's own rectangle: WebKit reports `innerWidth` and `innerHeight` as the visual size while pinch-zoomed, so clipping by them as well collapses a panned viewport to nothing. An open popover places itself again on `visualViewport` `resize` and `scroll`, once per frame, because an iOS pan and Chrome's resizes-visual keyboard fire neither a window resize nor a document scroll. A menu button at the end of a card inside much wider `bounds` passes `alignment: 'end'`; the automatic rule (a trigger in the start half of `bounds` aligns to its start) opened Home's Assistant Menu over the next card. Tests: `tests/unit/sillybunny-action-menu.test.js`, `tests/action-menu-viewport.e2e.js`.
- **`rem` does not follow the font slider:** the Global Font Size slider sets `--fontScale`, and `--mainFontSize` and every `--sb-type-*` token scale with it, but the root font size stays 16px, so a width in `rem` does not grow with the text. The art-and-text intro first stacked its line below the art at a `13rem` basis, which left about 18 characters per line beside 128px art at 20px text. `.sbArtIntro > p` uses `flex: 1 1 14em` in the line's own size (`public/css/sillybunny-windows.css`). Test: `tests/home-windows.e2e.js` (Shortcuts at 360×640 stacks at 20px text and sits beside its art at the default size).

### Scroll, streaming and cancellation

- **Breaks:** rendering or resizing moves the reader's position; cancelling leaves stream state behind.
- **Files:** `public/script.js`, `public/scripts/chat-render-lifecycle/`, `public/scripts/chats.js`, `src/request-cancellation.js`.
- **Guards:** `chat-render-lifecycle/scroll-intent.js` decides when to follow the newest message, `resize-observer.js` handles content that resizes after render, and `mobile-viewport.js` handles mobile viewport changes.
- **Guards:** a page hands its chat replies to the server and stops its stream on `pagehide`, not `beforeunload` (`public/scripts/resumable-generation.js`, `public/script.js`). A leave-site prompt can cancel `beforeunload`, and the page then stays with replies the server still writes into the chat (PR #877 review). Test: `tests/resumable-generation-frontend.test.js`.
- **Guards:** a freshly opened, greeting-only Reisen or Tewi chat stays at its top so the greeting picture is in view. The hold sits in the one bottom-scroll sink, `scrollChatElementToBottom`, through `shouldHoldChatAtTop()` (`public/scripts/sillybunny-home/greeting-art-opening.js`), and is not skipped for `force`, because the pins of a chat load are themselves forced. The resize compensation in `RossAscends-mods.js` writes `scrollTop` outside that sink, so it is guarded too: without it, the Temporary Chat banner moves the chat 46 px and ends the hold. A first version shadowed `#chat.scrollTop` with an own accessor; review found it swallowed the Go to bottom button and could snap back a scrollbar drag, so the sink guard replaced it. The hold must outlast the load lock (`script.js` 2400 + 250 ms); a unit test reads both. Tests: `tests/unit/sillybunny-greeting-art-opening.test.js`, `tests/greeting-art.e2e.js`.
- **Tests:** `tests/chat-render-lifecycle-script-wiring.test.js`, `tests/chat-scroll-regressions.e2e.js`, `tests/request-cancellation.test.js`, `tests/in-chat-agents-companion-panel.test.js`.
- **Fixes:** #271 (stabilise chat scrolling), #314 (cancel when a stream disconnects), #771 (resize and load lock work against each other), #783 (streaming moves the screen).

- **Files:** `public/scripts/extensions/in-chat-agents/agent-runner.js`, `agent-store.js`, `companion/companion-runner.js`, `companion/companion-panel.js`.
- **Tests:** `tests/in-chat-agents-runner.test.js`, `tests/guided-generations-profiles.test.js`, `tests/guided-generations-steering.test.js`.
- **No test:** `59aeea3f1` (#385, abort agent generation on cancel), `20353df60` (hotfix, swipes rerun agents).
- **Fixes:** #839 (Guided Generations cancel, swipe cleanup and profile restore).
- **Order matters:** Guided Generations calls `integrateQrBar()` before it returns for a hidden bar (`public/scripts/extensions/guided-generations/index.js`). If the order changes, Quick Replies show in the composer after a reload (`8ce1a10a5`). Test: `tests/guided-generations-settings.test.js`.
- **Dry runs:** the `GENERATION_STARTED` listener in `public/scripts/extensions/in-chat-agents/index.js` returns for a dry run, as the listeners in `agent-runner.js` and `public/scripts/sillybunny-conversation/init.js` do. A dry run does not change the generation state. Without the check, `refreshGenerationUi()` → `activateSendButtons()` → `showSwipeButtons()` → `refreshSwipeButtons()` added `.fade` to every rendered message. Prompt Manager starts dry runs from its own debounced timers after `CHAT_LOADED` (`saveServiceSettings()`, then `renderDebounced()`, in `public/scripts/PromptManager.js`), so one can land right after `redisplayChat({ fade: false })`. Holding `/api/settings/save` until after the redisplay reproduces the nightly failure in issue #920: 12 `.fade` classes in `redisplay keeps render follow-up hooks applied after batched render`. Tests: `tests/chat-scroll-regressions.e2e.js` (`a dry-run generation keeps redisplay follow-up hooks applied`), `tests/in-chat-agents-generation-ui-wiring.test.js`.

### Bundled defaults, templates and user state

- **Breaks:** a refresh, reset or update overwrites user themes or templates, or brings back deleted defaults.
- **Files:** `default/`, `public/scripts/preset-manager.js`, `public/scripts/extensions/in-chat-agents/agent-store.js`, theme endpoints and theme CSS.
- **Guards:**
  - `src/endpoints/content-manager.js` does not overwrite a seeded file that already exists.
  - "Restore default presets" (`restoreDefaultPresetFiles`, `src/endpoints/content-manager.js`) used `cpSync(..., { force: true })` over every bundled preset, so it reset bundled presets the user had edited while its confirm text promised only that deleted ones come back. It now copies with `COPYFILE_EXCL` and skips a file that exists, edited or not, including one that appears during the restore (`tests/default-preset-deletions.test.js`). Bundled Extras restores one preset through `/api/presets/restore` and `/api/presets/save` instead (`public/scripts/sillybunny-home/bundled-extras-presets.js`).
  - `reconcileManagedBundledQuickReplies()` removes a bundled Quick Reply only when its hash matches a known stale version. It does not touch user-edited files.
  - Bundled agent template updates match by template `id` (`scripts/bump-agent-template-versions.js`). An update keeps the agent's enabled state, quick-toggle pin, order and profile overrides.
  - `✅ Run Unit Tests on PR` fails when an existing bundled agent template or `index.json` entry changes without a version bump. It runs `scripts/bump-agent-template-versions.js --check` against the PR's merge ref. After a commit, bump with `npm run agents:bump-template-versions -- --base origin/staging`; without `--base` the script compares only uncommitted changes against `HEAD`.
- **Tests:** `tests/preset-save-deleted-default.test.js`, `tests/create-only-installs.test.js`, `tests/sillybunny-theme-css.test.js`, `tests/theme-custom-css-import.test.js`, `tests/in-chat-agents-templates.test.js`, `tests/bump-agent-template-versions.test.js`.
- **No test:** `a354f263d` (#753, redundant bundled-agent updates).
- **Fixes:** #687 (saving a preset over a deleted bundled default's name), #834 (an external theme pack wipes saved themes), #919 (theme data lost on update, export or reset; Custom CSS overwritten).
- **A bundled theme revision reaches users three ways:** new installs seed `default/content/themes/*.json` through `default/content/index.json` and take their applied palette from `default/content/settings.json`, which must match the default theme's file (`tests/libadwaita-theme-migration.test.js`). Existing installs keep their own copy, which `reconcileManagedBundledThemes()` (`src/endpoints/content-manager.js`) replaces only when its SHA-256 equals a previous bundled file (`MANAGED_BUNDLED_THEMES`, `CONTRAST_REVISED_THEME_HASHES`), so edited and deleted copies stay as they are. The colours a user has applied live in their own `settings.json`, which only a startup repair changes: `planThemeTextRepair()` (`public/scripts/sillybunny-theme-revisions.js`), run once from `public/scripts/power-user.js` behind `power_user.sb_theme_text_revision`, acts only when the saved theme name and all ten colour keys equal a previous bundled version, and replaces the CSS only when it is the previous bundled CSS. Without that repair a user keeps the old colours, and switching themes later shows the prompt for CSS no theme stores. Tests: `tests/bundled-theme-reconcile.test.js`, `tests/sillybunny-theme-revisions.test.js`, `tests/sillybunny-theme-text-repair.e2e.js`, `tests/bundled-theme-text-contrast.test.js` (every bundled theme's text roles reach 4.5:1).
- **Bundled extensions open their own first-run dialogs:** Quick Image Gen opens its setup wizard whenever its saved settings are missing or empty (`public/scripts/extensions/quick-image-gen/index.js`), which happens on a new install, after a settings reset and after an import without its settings. On a first run the wizard sat under the modal onboarding dialog, where its Skip button could not be pressed, and `waitForAppReady()` (`tests/frontend/frontent-test-utils.js`) needed a locator handler to close it. `seedQuickImageGenFirstRun()` (`public/scripts/sillybunny-first-run-defaults.js`), called once before `loadExtensionSettings()` in `public/script.js`, seeds `{ setupWizardSeen: true, starterPresetsSeeded: false }`: QIG treats any non-empty saved object as an existing install, so `starterPresetsSeeded` must be an explicit `false` or the starter presets are skipped too. The vendored files are unchanged. Tests: `tests/unit/sillybunny-first-run-defaults.test.js`, `tests/quick-image-gen-first-run.e2e.js` (with the seam disabled, the no-wizard and reset tests fail; without the explicit `false`, the starter-presets test fails).
- **What the app rewrites when a card is saved:** the character editor posts `FormData`, and the browser sends its multi-line text with CRLF line breaks; `charaFormatData` (`src/endpoints/characters.js`) writes an `extensions.depth_prompt` with an empty prompt into every card it saves, and the editor embeds the linked world as `data.character_book` under the world's name. A fingerprint of a card's text must normalise all three, or saving a bundled card without a change makes it look edited. `src/sillybunny-managed-content.js` normalises line breaks, treats an empty depth prompt and a book named after a manifest world as none, and pins literal hashes so the algorithm cannot drift without a failing test (`tests/managed-content-app-roundtrip.test.js` posts real CRLF multipart through `/edit`).
- **Managed bundled content never overwrites what it does not recognise:** reconcile replaces a card, sprite file or world only when its fingerprint is a known earlier release; anything else (a user edit, a malformed or unsafe file) is `modified` and left alone, and only an explicit apply or restore writes it, after a backup that aborts the write when it fails. A world's root `extensions` count, because the app copies them into embedded books. Renaming a managed card moves its file, so it shows as `deleted` and Restore adds a second card (`tests/managed-content-app-roundtrip.test.js`).
- **The default assistant is remembered, so its cache must follow the character list:** `public/scripts/sillybunny-home/default-assistant-resolver.js` keeps the answer per `characters` array by identity and length, because each item of one list render asks for it. The array is refilled in place, so identity alone kept a stale answer; `public/scripts/welcome-screen.js` also clears the cache on `CHARACTER_PAGE_LOADED`, `CHARACTER_EDITED`, `CHARACTER_DUPLICATED`, `CHARACTER_RENAMED` and `CHARACTER_DELETED`, registered after the handlers that change the identity avatar and the deletion marks. A server-seeded assistant (Reisen, Tewi) has no creation method, so the bundled fingerprint check must match it by avatar alone; reading its title threw `TypeError … toLowerCase` while a pointer named the deleted card. Tests: `tests/unit/sillybunny-default-assistant-resolver.test.js`, `tests/bundled-assistants.e2e.js`; review `ses_e6bdd0f01ffeY4maAD47mMHxoC`.
- **An unnamed account's persona is `'[Unnamed Persona]'`, not `'User'`:** `addMissingPersonas` (`public/scripts/personas.js`, called from `getUserAvatars`) binds every avatar without a persona to the name `'[Unnamed Persona]'` with empty fields at boot, while `name1` stays `'User'`. A check on the name `'User'` alone never matched a real account, so Welcome's reopen form missed the untouched default; `isUntouchedDefaultPersona` (`public/scripts/sillybunny-welcome-persona.js`) accepts `'User'`, `'[Unnamed Persona]'` or no bound name, with an empty description, title and lorebook, no connections or appendices, and not the account's default persona. Tests: `tests/unit/sillybunny-welcome.test.js`, `tests/welcome-startup.e2e.js`.

### Chat writes, reloads and backups

- **Breaks:** an old queued write replaces a newer chat; backups push each other out of the backup ring.
- **Files:** `public/scripts/chat-save-guard.js`, `public/scripts/chat-reload-guard.js`, `src/endpoints/chats.js`, `src/generation-commit.js`, `public/scripts/server-generations.js`.
- **Guards:**
  - The server writes a reply over an existing message only when that message carries `extra.server_generation_placeholder` with the generation's start time. The browser removes the mark when the reply is finished, so a reply the page saved itself, and later edits to it, are not overwritten (`src/generation-commit.js`).
  - `Generate()` awaits `settleGenerationCommit()` before it saves a finished reply. If the server answers `committed`, the page reloads the chat and does not save its own copy, which would fail the integrity check. Stream readers return at `[DONE]`, which can come before the body ends and claims on its own (PR #877 review).
  - A tab keeps its server event stream (`public/scripts/server-generations.js`) only while it is visible or reads a reply of its own. Over HTTP/1.1 a browser opens about 6 connections per server for all its tabs; with a stream in every tab, a seventh tab never loads (PR #877 review). Tests: `tests/server-generations-frontend.test.js`, `tests/server-generation-commit.e2e.js`.
  - A tab that reloaded once for a server-written reply and still finds no mark for it acknowledges it. Otherwise each reload reconnects, hears of the reply again and reloads again until the server forgets it.
  - `reloadCurrentChat()` removes an open message editor but leaves `this_edit_mes_id` set. A reload for a server-written reply reopens the edit with its unsaved text through `messageEdit()`, unless the reply changed that message, and clears the id with `setEditedMessageId()` (`restoreOpenEdit()` in `public/scripts/server-generations.js`). Waiting with the reload does not help: once the server has written the chat, saving the edit fails the integrity check. Tests: `tests/server-generations-frontend.test.js`, `tests/server-generation-commit.e2e.js`.
  - A temporary chat writes nothing because one flag (`public/scripts/sillybunny-temporary-chat-state.js`) is checked at each seam that reaches the server or the card: `saveChatImmediately()`, `saveChatDebounced()`, `updateRemoteChatName()`, `statMesProcess()` (`public/scripts/stats.js`), `getOpenChatTarget()` (`public/scripts/server-generations.js`), `clearChat()`'s itemized-prompt save, the settings payload's `active_character`, and the chat collection in `public/scripts/extensions/vectors/index.js`. The flag check must not compare the selected card: when a route changed the card without leaving, the next save would write the temporary messages into the other card's real chat. `reloadCurrentChatUnsafe()` ends the temporary chat instead when the card no longer matches. Tests: `tests/temporary-chat.e2e.js` (no write outside an allowlist), `tests/temporary-chat-seams.test.js`, `tests/temporary-chat-navigation.test.js`.
  - Every route out of a chat passes `flushPendingChatSavesForNavigation()` before `setCharacterId()`. `/go` and `/char` (`openChat()` in `public/scripts/slash-commands.js`) and `/random` (`doRandomChat()` in `public/scripts/power-user.js`) set the new card first, so a review probe saw a pending save of the old chat sent with the new card's file name and avatar, and a temporary chat stayed on under another card. Both now flush first and stop on false (`tests/temporary-chat-navigation.test.js`).
  - `doNewChat()` with "delete current chat" deletes the chat named in the card, which after a discarded temporary chat is the character's real chat. It skips the delete when the open chat was temporary (`tests/temporary-chat-seams.test.js`, red before the fix).
  - "Nothing changed since the user chose Discard" must compare the messages, not `chat.length`: an edit, a swipe or a continue keeps the length, so the next leave dropped an edited temporary chat without asking. `leaveTemporaryChat()` (`public/scripts/sillybunny-temporary-chat.js`) compares each message's `mes` and `swipe_id`.
- **Tests:** `tests/chat-cloning-lifecycle.test.js`, `tests/chat-save-guard.test.js`, `tests/chat-save-queue-runtime.test.js`, `tests/chat-integrity-rotation.test.js`, `tests/reload-chat-safeguard.test.js`, `tests/prove-368-differential.test.js`, `tests/server-generation-commit.test.js`, `tests/resumable-generation-frontend.test.js`, `tests/story-mode-request-controls.test.js`.
- **Fixes:** #819 (queued saves across swipes clone chats), #849 (staged reloads wipe chats), #373 (extra pre-write backups push older backups out), #856 (issue #706: a chat saves when opened).

### Dialog adapters and legacy DOM

- **Breaks:** moving Chat History controls into a shared Window can lose the original cleanup tree, leave dynamically created backup nodes behind, or return focus to a detached mobile sheet action.
- **Guard:** record source parents, sibling positions, child order and hidden state before adoption; restore the source before removing the page and use a connected mobile chat-chip fallback when the sheet opener is disposed. Keep backup visibility driven by the list-page parent state.
- **Tests:** `tests/unit/sillybunny-chat-dialogs.test.js`; `tests/sillybunny-overlays.e2e.js`; `tests/mobile-shell-smoke.e2e.js`; `tests/mobile-character-toggle-and-panels.e2e.js`.
- **Hash links under `<base href="/">`:** `public/index.html:6` sets `<base href="/">`, so a hash-only link such as `href="#bg_global_tab"` resolves to `/#bg_global_tab`, not to the current URL. jQuery UI 1.13.2 tabs (`_isLocal`) compare that with `location.href`, so with any query string in the page URL (the login redirect keeps the query, logout adds `?noauto=true`) the Backgrounds tabs counted as remote and `load()` fetched `/` into a new panel: a second copy of the app whose `#sheld` and `#chat` came first in document order, which broke Home. It shows only after first run, because `initBackgrounds()` runs after onboarding; upstream SillyTavern has the same markup (`1da6e4012`). Guard in `public/scripts/backgrounds.js` (`initBackgrounds`): `aria-controls` on each tab `<li>` from its anchor's hash, `tabs({ beforeLoad: event => event.preventDefault() })`, and the `aria-live` jQuery UI puts on "remote" panels removed. An unhandled `href="#"` click under `<base>` navigates to `/#`, a full reload when the page has a query; the existing handlers call `preventDefault`. Guards: `tests/css-has-scope.test.js` (an allowlist of document-level `:has()` rules, three left on purpose) and `tests/has-scope.e2e.js`. For list builds the scope matters less (see the boxed-list entry); for streaming it is the main lever. Fix: #870 (`:has()` scoping).
- **A hidden element is still a description:** the accessible name and description computation includes a hidden element when `aria-labelledby` or `aria-describedby` points straight at it, so hiding a tile's voiced line in Compact left it in the tile's description. Home tiles are named by their title and described by the line and progress (`public/scripts/sillybunny-home/tiles-view.js`), and `describeTiles()` rebuilds each `aria-describedby` after a display mode change (`public/scripts/sillybunny-home/mount.js`). Test: `tests/home-layout.e2e.js` (accessible name and description in Full and Compact).
- **A page that loads its content shows it in place:** Help topic pages take their body from a template (`public/scripts/templates/help/<id>.html`). Built first and filled later, a topic page painted the `TODO(copy)` placeholder and then swapped in the template, which would flash once real text lands, and a slow load could land over a page the user had picked since. `loadViewBody()` (`public/scripts/sillybunny-help/help-views.js`) loads the template before the page is built, and `createMoveRunner()` (`public/scripts/sillybunny-help/move-runner.js`) drops a move that a later move or a closed window has overtaken. Tests: `tests/help-shortcuts.e2e.js` (the page enters the document once with its body; two quick clicks keep the second body; a failed template falls back to the marked placeholder), `tests/unit/sillybunny-help-move-runner.test.js`.
- **App-wide keys and other modals:** F1 (Help) and Ctrl+? or Cmd+? (Keyboard Shortcuts) open nothing while another modal is open, but still hold back the browser's default, so the key behaves the same everywhere (`hasOtherModalOpen()` in `public/scripts/sillybunny-help/help-keys.js`). The modifier is Cmd on Apple platforms and Ctrl elsewhere, never Meta on Windows or Linux (Super) and never with Alt, because Windows reports AltGr as Ctrl+Alt and a layout that types `?` with AltGr would lose the key in every text box (DESIGN.md § Keyboard). Tests: `tests/unit/sillybunny-help-keys.test.js`, `tests/help-shortcuts.e2e.js`. A headless browser cannot show whether F1's own browser help or the macOS Help-menu search is suppressed; check those by hand.
- **One Escape, one question:** Chromium closes a modal `<dialog>` again after a `cancel` that was prevented, from the third Escape on, so one key press can deliver both `cancel` and `close`. The frame's `close` handler then asked `canClose` a second time, and Welcome went back two pages on one Escape. `openDialog()` (`public/scripts/sillybunny-editor/dialog.js`) records that the `cancel` handler answered this key press and skips the extra ask in `close`. Test: `tests/sillybunny-dialog-frame.e2e.js` ("each Escape asks the dialog once, also the third").
- **The deferred window stylesheet wins over Home's rules of equal weight:** `public/css/sillybunny-windows.css` is loaded by script with the first window (`public/scripts/sillybunny-window-styles.js`), after `sillybunny-home.css`, so an unscoped 64px size for a Bundled Extras row's art (`.sbHomeArt[data-sb-art-placeholder='row-nahida']`, since removed with that row) shrank a Home card's art from 128px to 64px once any window had opened, while a sizing test that ran before any window passed. A rule in that sheet for art that Home also draws must be scoped to its window (for example `.sbBundledExtrasDialog …`). Test: `tests/home-assistants.e2e.js` ("keep the box of their art once a window has opened") opens and closes Bundled Extras, then checks that every Home assistant card's art box is unchanged.
- **Floating entry rows never show a placeholder at rest:** `createEntryRow({ floating: true, placeholder })` moves the hint into `data-sb-floating-placeholder` and `aria-description` (`prepareFloatingPlaceholder`, `public/scripts/sillybunny-editor/rows.js`) and sets the real placeholder to a space, and `public/css/sillybunny-tabs.css` makes `::placeholder` transparent, raising the title only on focus or with a value. A row that must show a hint (Welcome's reopen name field, hint "User") sets `control.placeholder` after the row is built and takes the class `sbWelcomeNameHint`, which `public/css/sillybunny-windows.css` uses to raise the title and show the hint.
- **Forced colours: rows, flat buttons and trail links need an edge of their own or their list's:** in forced-colours mode a `.ds-row` is bounded by its boxed list's outline and the separators between rows, as libadwaita draws high contrast, and the accessibility probe accepts that (`isBoundedByList`, `tests/helpers/dialog-accessibility.js`); Home's flat buttons (Show Me, Skip, Learn More, Install) had no edge at all and now take a 1px `ButtonBorder` outline, and Help's breadcrumb links take an underline (`public/css/sillybunny-windows.css`).
- **Forced colours: a focus ring must not match what is behind it:** a focused, checked switch drew its `Highlight` ring on its own `Highlight` fill, so the ring vanished. Forced colours now draw a `CanvasText` ring 2px outside the track (`public/css/sillybunny-theme.css`), and the probe's `outlineOnBackdrop` fails a ring that matches its backdrop. Room in the blocking sheet came from merging seven `.checkbox_label > input[type="checkbox"]:X, input[type="checkbox"].sb-switch:X` pairs into `input[type="checkbox"]:is(.sb-switch, .checkbox_label > *):X` (same specificity).
- **Window widths that hold labels scale with the text size:** Help's sidebar was a fixed 220–360px, so at 200% text its section names broke inside a word; `help-window.js` multiplies both limits by `--fontScale` (`readTextScale`). The 600px collapse point stays unscaled, because scaling it moved the Help intro line off the art (`tests/home-windows.e2e.js` Intros).
- **Window rows wrap instead of breaking words:** the shared `.ds-row-text { overflow-wrap: anywhere }` (`public/css/sillybunny-tabs.css`, a blocking sheet with no room) broke labels letter by letter on a phone at 200% text when keycaps, chips or buttons shared the line. Keyboard Shortcuts, Getting Started, Bundled Extras and Help opt out in `public/css/sillybunny-windows.css` with `flex-wrap` on the row and `min-inline-size: min-content; overflow-wrap: break-word` on the text, so the suffix drops below the label; Getting Started's nowrap note line needs `contain: inline-size` so it is not measured as a word. Tests: `tests/dialogs-accessibility.e2e.js` (200% text, no clipped labels).
- **Long boxed lists are built in growing chunks:** each row appended to a window's boxed list restyles and lays out the rows already in it, so the cost of an append grows with the list. Building all 3,000 rows of a large library in one insertion held the Choose Assistant window for about 0.35 s before its first paint, and fixed 60-row chunks took several seconds to finish. `public/scripts/sillybunny-home/assistant-picker.js` builds the first 40 rows, and the rows down to just below the selected one, before the window opens, then appends one chunk per frame that grows with the list (60 to 500 rows), filters late rows against the current search, and stops when the window closes. Rows are only appended, never inserted above the focused one, so the first insertion still grows with the selected row's position (about 0.9 s at row 1,500 of 3,000). Deleting most `:has()` rules cut the total build time by only about 29% in review, so scoping selectors is not the main lever. Tests: `tests/unit/sillybunny-assistant-picker.test.js` (`83ac928b8`).
- **A control that hides when the list fits one page is a one-way door:** `createListPagination` (`public/scripts/sillybunny-editor/list-pagination.js`) hid its whole bar, page-size control included, while the list fitted one page, so choosing a size larger than the World Info book or the persona list hid the only control that could undo it. The bar now hides only while the list is no longer than the smallest page size; `keepSizeVisible` (Characters, Groups) still keeps it for any nonempty list. The bar hides through `.sb-list-pagination[hidden]` rules (`sillybunny-editor-shell.css`, `sillybunny-entity-list.css`), because the class sets `display: flex`. Tests: `tests/unit/sillybunny-list-pagination.test.js`, `tests/unit/sillybunny-persona-editor.test.js`, `tests/world-info-editor.e2e.js`, `tests/persona-editor.e2e.js`. Fix: #870 (page-size control).

### Provider errors and connection feedback

- **Breaks:** a failed request shows only the HTTP reason phrase ("Bad Request", "Unauthorized"), so a bad key, a missing model and a provider outage look alike.
- **Files:** `public/scripts/sillybunny-request-errors.js`, `public/scripts/sillybunny-provider-message.js`, the failed-response sites in `public/script.js`, `public/scripts/openai.js`, `textgen-settings.js`, `kai-settings.js`, `nai-settings.js`, `horde.js` and `custom-request.js`, and on the server `src/util.js` and `src/endpoints/backends/chat-completions.js`.
- **Guards:** `showRequestError` shows the provider's own message, with a hint for 401/403, 404, 429 and 5xx. The server turns a provider 401 into 400 so the browser keeps its Basic auth, and sends the original status in `X-Upstream-Status`, which `getFailureStatus` reads.
- **Guards:** `extractProviderMessage` gives up only on a top-level body that looks like JSON and does not parse. A nested message that starts with `[` or `{`, such as `[400 Bad Request] API key not valid`, is the provider's own sentence; dropping it left the toast with the bare reason phrase.
- **Guards:** Send with no connection (`online_status` `no_connection`, or not known yet) shows the "Not connected to API!" notice, whose Show Me opens Connections, and leaves the draft in the box (`sendTextareaMessage` and the Send button handler in `public/script.js`, `public/scripts/sillybunny-connection-notices.js`). Before, Enter posted the user's message with no reply and no word why. Slash commands still run offline.
- **Keyboard presses are untrusted clicks:** upstream `public/scripts/keyboard.js` turns Enter on a `<div class="menu_button">` into `target.click()`, which has `isTrusted: false`. Telling a user's Connect from an automatic one by `isTrusted` left keyboard users without the missing-key feedback; `onConnectButtonClick` in `public/scripts/openai.js` checks for `e.originalEvent`, which jQuery's `.trigger('click')` does not set.
- **A toast's own `onHidden` replaces the global one:** toastr's per-toast `onHidden` overrides the global hook that calls `fixToastrForDialogs()` (`public/script.js`), so the connection notices call it themselves.
- **Invalid fields lost their focus colour:** surface focus rules that include an id, such as `#sb-settings-page … input:focus`, beat `[aria-invalid]:focus`, so a focused invalid field looked like any focused field. `:is(.text_pole, select)[aria-invalid='true']` sets `--sb-composer-focus-border` and `--sb-composer-focus-ring`, which those rules read (`public/css/sillybunny-theme.css`); no `!important`.
- **Tests:** `tests/sillybunny-request-errors.test.js` (the message matrix), `tests/sillybunny-request-error-sites.test.js` (the Kobold, NovelAI, Horde and custom-request sites), `tests/request-errors.e2e.js`, `tests/sillybunny-connection-notices.test.js`, `tests/connection-notices.e2e.js` (Enter on a focused Connect button included).
- **Fixes:** #870 (request errors; Send and Connect feedback).

### Upstream compatibility and sync

- **Breaks:** the version map reports the wrong SillyTavern base, so extensions that need a newer SillyTavern fail.
- **Files:** `docs/upstream-sync.md`, `public/scripts/sillybunny-version-map.js`, `public/scripts/openai.js`, `src/endpoints/backends/`.
- **Guards:** the version map clamps a SillyBunny version with no mapping to the highest synced SillyTavern version for its major.
- **Tests:** `tests/sillybunny-version-map.test.js`, `tests/upstream-provider-parity.test.js`.
- **Third-party settings drawers lost their page when settings became a page list:** extensions that predate the Extensions panel append their `.inline-drawer` to `#user-settings-block-content`, and the settings split leaves that column unpainted (`buildShell`, `public/scripts/sillybunny-tabs.js`), so such a drawer measured 0×0 and showed on no settings page; the old four-tab `data-active-tab` filter it had relied on no longer existed, and `tests/topbar-extension-adoption.e2e.js:265` failed on the base `f6c1b217b` too. `public/scripts/sillybunny-settings-stray-drawers.js` moves (never clones) each direct-child drawer of that column into `#extensions_settings2`, now and through a `MutationObserver`, so the Extensions page lists it as a user-installed row; authored drawers deeper in `#UI-Customization` stay. Tests: `tests/topbar-extension-adoption.e2e.js`, `tests/unit/sillybunny-settings-stray-drawers.test.js`.

Tests: `tests/unit/sillybunny-keyboard-enter.test.js`, `tests/dialogs-accessibility.e2e.js`.
